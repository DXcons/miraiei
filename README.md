# 未来栄株式会社 図面管理システム

未来栄株式会社向けWebアプリです。ログイン認証とPDF図面の保存・検索をFirebase（Authentication + Firestore）を
使った実データで行います。

## 画面構成

## セットアップ（Firebase連携）

1. [Firebaseコンソール](https://console.firebase.google.com/) で新規プロジェクトを作成する。
2. **構築 > Authentication** を開き、「始める」→ ログイン方法で **メール/パスワード** を有効化する。
   （本アプリにサインアップ画面はないため、利用者アカウントは次の手順でしか作られません）
3. **Authentication > Users** タブから「ユーザーを追加」で、利用者ごとにメールアドレス／パスワードを登録する。
4. **構築 > Firestore Database** を開き、「データベースの作成」（本番環境モードで作成）。
5. Firestoreの **ルール** タブを開き、いったん以下の内容に置き換えて「公開」する（データ投入のため一時的に書き込みを許可）。
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /drawings/{drawingId} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
6. **プロジェクトの設定(歯車アイコン) > 全般** の「マイアプリ」でウェブアプリを追加し、表示された`firebaseConfig`の値を
   [`js/firebase-config.js`](js/firebase-config.js) に貼り付ける。
7. 変更をコミットしてGitHubへpush（GitHub Pagesに反映されるまで数分待つ）。
8. 公開されたサイトで手順3のアカウントでログインし、`seed.html` を開いて「ダミーデータ12件を投入する」を実行する。
9. 投入完了後、`seed.html` を削除し、Firestoreのルールを [`firebase/firestore.rules`](firebase/firestore.rules) の内容
   （読み取り専用）に戻して再度「公開」する。

`js/firebase-config.js` の値はクライアント側に公開される前提の識別子です。データの保護はFirestoreの
セキュリティルール（`drawings`はログイン済みユーザーのみ閲覧可・書き込み不可）で行っているため、
リポジトリに含めても問題ありません。

## 使い方

**必ず公開URL（https://dxcons.github.io/miraiei/ ）から開いてください。**
パソコン上のファイルを直接（`file://`）開くと、ブラウザのセキュリティ制限でCSVの読み込みが
ブロックされ、客先一覧や品名候補が表示されません。

セットアップ手順3で作成したメールアドレス・パスワードでログインします。

## PDF図面の保存（図面を保存する）

ホームの「図面を保存する」から、PDFの図面を **客先／図面作成日／品名** とあわせてFirestoreに登録します。

画面は「入力が必要な項目」と「任意で入力する項目」の2つに分かれています。

- **入力が必要な項目**：PDFファイル（＋ファイルごとの品名）→ 客先 → 図面作成日 の順で入力します。
  図面作成日は年・月とも「不明」を選べます（年が不明の場合は月も自動的に不明になります）
- **任意で入力する項目**：設置場所（屋外／屋内）、材質（樹脂／金属）、大きさ（大物／小物）、
  種別（ベルトコンベヤ／それ以外）。あとで探しやすくするための分類で、未入力でも保存できます。
  普段は折りたたまれており、見出しの「＋」を押すと開きます（選択済みの内容は見出しの右に表示）。
  ここで選んだ内容は、そのとき選択しているPDF全部に共通で付きます

任意項目の選択肢は [`js/pdf-store.js`](js/pdf-store.js) の `PDF_OPTION_FIELDS` で定義しており、
保存画面の選択肢と検索画面の絞り込みが同じ定義を共有しています。項目や選択肢を増やしたいときは
この配列を編集すれば、両方の画面に自動で反映されます。

### 保存のしくみ

Firebase Storage（ファイル保管庫）は有料のBlazeプランが必須のため、本アプリでは使いません。
代わりに、PDFをBase64文字列に変換して **Firestoreに分割して保存** しています（[`js/pdf-store.js`](js/pdf-store.js)）。
これにより無料のSparkプランのまま、クレジットカード登録なしで運用できます。

```
pdfDrawings/{id}                … 客先・図面作成日・品名・ファイル名・サイズなど（検索用）
pdfDrawings/{id}/chunks/{nnnn}  … PDF本体を50万文字ずつに分割したBase64データ
```

Firestoreは1ドキュメント約1MBが上限のため50万文字ずつに分割し、読み出し時に結合して元のPDFに戻します。

### 制限と目安

| 項目 | 値 | 備考 |
|---|---|---|
| 1ファイルの上限 | 20MB | 超えるファイルは選択時に弾かれます |
| 保存できる合計容量 | 約1GB（Firestore無料枠） | Base64化で約1.34倍になるため、実PDFで約750MB相当 |
| 1日の書き込み回数 | 20,000回（無料枠） | 0.5MBごとに1回。3MBのPDFなら1件あたり約8回 |

容量が足りなくなった場合は、Firebaseを**Blazeプラン**に切り替えてFirebase Storageへ移す方法が
あります（この構成からの移行は、保存先を差し替えるだけで済むように分離してあります）。

### 客先一覧

「客先」の選択欄は、保存画面の右上にある「客先一覧の編集」ボタンから追加・削除・名称変更ができます。
保存した一覧はFirestoreの `settings/customers` に入り、全員・全PCで共有されます
（`firebase/firestore.rules` の `settings` の許可をFirebaseコンソールに反映しておく必要があります）。

一度も編集していない間は、[`data/customers.csv`](data/customers.csv) の内容が初期値として表示されます。

一覧にない客先は、選択欄の「＋ 一覧にない客先を直接入力する」を選ぶと自由入力できます。

### 受発注・請求書の管理

`orders.html`。取引1件をFirestoreの `orders` コレクションに1ドキュメントとして保存します
（列: 納期・受注拠点・客先名・品名・金額（税抜）・見積番号・ステータス・請求日・備考）。
ステータスを「請求済み」にしたとき請求日が空なら、その日の日付が自動で入ります。

各取引の「📎 書類」から、見積書・納品書・請求書・写真などのファイルを保存・表示できます
（Firestoreの `orderFiles` に図面と同じ方式で分割保存。写真は長辺2400pxのJPEGに縮小して保存）。
図面は「図面を保存する」で保存済みのものを `orders/{id}.drawingIds` で紐づけるだけで、二重には保存しません。
取引を削除すると、その取引の書類も削除されます（紐づけた図面は残ります）。

### 案件（2026-10-11の作り直し）

案件＝**客先グループ＋品番**（DIDは注文番号）。次の3つを案件ページ（`case-detail.html`）に集めた。

- **納期・ステータス**：受発注・請求書の管理の取引（`orders`）と同じデータ。取引に `caseCode`（品番）を持たせて対応させる
  （`js/order-store.js` の `findCaseOrder`）。受発注の一覧の「品番」欄から案件ページへ飛べる。
- **書類**：`orderFiles` に保存。案件ページで追加した書類は `orderId` に案件キー（`caseKeyOf(客先グループ, 品番)`）を入れるので、
  取引を登録する前でも書類を貯められる。受発注の一覧の「📎 書類」にも同じ書類が出る。
- **突き合わせ表**：`caseItems`。「＋ 行を追加」で手入力（進行中の案件）、「📥 まとめて取り込む」でJSON/電子PDF（納品済みの案件）。
  取り込みは、同じ案件・同じ図面番号の行（手入力の行を含む）を上書きするので二重にならない（`resolveImportTargets`）。

**進行中／過去の分け方**：取引があり、ステータスが「入金済み」「受注せず」でない案件が進行中。それ以外
（入金済み・受注せず・取引の無い取り込み案件）が過去。入金済みにすると自動で過去の一覧に移る。

使い方の2パターン：
1. 納品済みで書類がそろっている → 案件ページに書類を追加し、点数が多ければClaude CodeでJSONを作って取り込む。
2. 進行中 → 書類が届くたびに案件ページへ追加し、分かった単価から行に入れる。最後にステータスを進める。

### 受注単価・外注単価の突き合わせ（過去の図面をさがす）

ホームの「過去の図面をさがす」→ 客先（CAM'S／神栄／DID／その他）→ 品番（案件）を選ぶと、
注文書（客先→未来栄）の受注単価と、御見積書（外注先→未来栄）の外注単価を突き合わせた表が出ます。
列は 品番・商品名・図面番号・受注単価・外注単価・外注先・受注年月日・図面表示 です。

- 突き合わせのキーは **図面番号**（注文書の「10202」＝御見積書・図面の「MN-10202」）。品番＋品名では
  同名の部品（搬送レール×6など）を区別できないため。
- 客先の4分類は [`js/case-store.js`](js/case-store.js) の `CASE_CUSTOMER_GROUPS`。表記ゆれは `aliases` に足す。
- 表の「修正」で、商品名・単価・外注先・受注年月日・メモ・要確認の印を直せます。
- **外注先が複数ある部品**（DIDのように材料・熱処理・加工を別々に手配するもの）は、明細の `costs` に
  工程ごとの外注先・単価を持ち、外注単価はその合計です。表では外注先が「金太 ほか3社」と出て、
  「内訳▾」で工程ごとの内訳が開きます。内訳は「修正」から追加・変更できます。
- 外注単価には **材料費・運賃も含める**（出ていくお金はすべて含める方針）。見積はもらったが発注しなかった先
  （例：伸栄の案件でテルミックが全点見積したが、BPはタツミ精機に発注）は `kind: "reference"` の参考行として
  内訳にグレーで表示し、合計には含めない。「修正」の内訳で「参考」にチェックすると同じ扱いになる。
- 「品番」列の呼び方は客先ごとに `codeLabel` で設定（DIDは外作依頼書の「注文番号」）。
- 検索は英語の品名もカタカナでヒットします（SHAFT⇔シャフト、半角カナ・ひらがな・長音の有無・
  図面番号のハイフンの有無も問わない）。英語→カタカナの対応表は `PART_NAME_EN_TO_KANA`。

**データの作り方**：PDFはスキャン画像で文字データが無く、受注単価は手書きのため、Claude Codeで
PDFを読み取って「取り込み用ファイル（`○○_取り込み用.json`）」を作ります。図面は1枚ずつのPDFに分けて
同じファイルに入れています。取り込み用ファイルは **アプリのフォルダ（GitHub）には入れない** でください
（単価が入っており、GitHub Pagesは誰でも見られるため）。置き場所は `03_未来栄/取り込みデータ/`。

**メールで届いた電子PDFの場合**：`case-import.html` で客先を選び、注文書・御見積書・図面のPDFを
まとめてドラッグ＆ドロップすると、ブラウザの中で読み取って同じ確認表を作ります（[`js/pdf-text-import.js`](js/pdf-text-import.js)。
pdf.jsで文字と位置を取り出し、表の見出しの位置で列を判定）。突き合わせは 図面番号＋品名 → 品名のみ → 図面番号のみ
の順で行い、食い違いは「要確認」と「読み取りで気になった点」に出します。注文書の書式は客先ごとに
`PDF_IMPORT_FORMATS` に登録（いまはCAM'Sのみ）。スキャン・FAXの画像PDFは読めないので、下の取り込み用ファイルを使います。

**取り込み**：`case-import.html` で取り込み用ファイルを選ぶ → 表で内容を確認（伝票ごとの合計が紙の合計と
一致するかも表示）→「保存する」。同じファイルを取り込み直すと上書きされます。

```
caseItems/{id}            … 明細(図面1枚=1件)。idは 客先・品番・図面番号・伝票番号 から決まる
pdfDrawings/{id}          … 図面。「図面を保存する」と同じ置き場所なので、保存したPDF図面の検索にも出る
caseDocs/{id}/chunks/…    … 元の注文書・御見積書のPDF
```

### 保存容量の目安

「図面を保存する」画面と書類画面に、Firestore無料枠（1GiB）に対する使用量の概算を表示します。
ファイルサイズ×4/3（Base64化の分）から計算した目安で、正確な値はFirebaseコンソールで確認してください。ステータスの選択肢と並び順は
[`js/order-store.js`](js/order-store.js) の `ORDER_STATUSES` で定義しています。
客先名の選択肢は「客先一覧の編集」で登録した一覧を共用します。

### 品名の入力補完

「品名」欄は自由入力ですが、入力欄をクリックすると [`data/products.csv`](data/products.csv) に載っている
品名を候補パネルから選べます。候補は過去の図面（CAM'S様の図面例など）に実際に記載されていた品名を
もとにした初期リストです。候補にない品名もそのまま入力できます。

候補パネルは2段階になっています。

1. 最初に「複数部品の図面」（1つのPDFに複数の部品が載っている場合に使う特別な項目）と、
   50音の行（あ行・か行・さ行…）のボタンが並びます
2. 行のボタンを押すと、その行に属する品名の一覧が出て、クリックすると入力欄に反映されます

`data/products.csv` は「品名,よみ」の2列のCSVです。よみ（ひらがな）の1文字目をもとにどの行に
表示するかを自動判定します。よみを空欄にすると、「複数部品の図面」のように50音の行に属さない
特別項目として、パネルの先頭に常に表示されます。候補を追加したいときは、この2列の形式で
1行ずつ追記してください（例：`プーリー,ぷーりー`）。

さらに、**保存済み図面で実際に使われている品名も自動で候補に加わります**。そのため、候補になかった
品名を直接入力して保存すると、次回からはその品名が候補に出るようになります。カタカナ・ひらがなで
始まる品名は該当する行に、漢字や英字で始まる品名は「その他」に分類されます（「その他」のボタンは
該当する品名がある場合のみ表示されます）。

なお、CSVが読み込めない環境（ローカルファイルとして開いた場合など）でも候補が消えないよう、
同じ初期リストを [`js/pdf-store.js`](js/pdf-store.js) の `DEFAULT_PRODUCT_ITEMS` にも持たせています
（客先は `DEFAULT_CUSTOMERS`）。CSVが読める場合はCSV側が優先されるため、通常の運用では
CSVだけ更新すれば問題ありません。

### セキュリティルールの更新

この機能を使うには、Firestoreのルールに `pdfDrawings` の設定が必要です。
[`firebase/firestore.rules`](firebase/firestore.rules) の内容をFirebaseコンソールの
**Firestore Database > ルール** に貼り付けて「公開」してください。

## 注意事項

- **動作確認は必ず公開URL（https://dxcons.github.io/miraiei/ ）で行ってください。** ローカルファイル
  （`file://`）で開くとCSVの自動読み込みがブラウザにブロックされ、客先一覧や品名候補が正しく出ません。
- ログイン状態はFirebase Authのセッション（ブラウザのローカルストレージ）で管理されます。
- ログイン済みのユーザーであれば、誰でも他の人が保存した図面を閲覧・削除できます（利用者ごとの
  権限分けはしていません）。削除は取り消せません。
- PDFの種類・サイズ（20MBまで）のチェックは画面側でのみ行っています。Firestoreのルールでは
  制限していないため、厳密な制限が必要になった場合はルール側の対応が必要です。
